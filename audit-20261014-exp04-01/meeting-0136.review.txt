PILOT SMALL FACTS
1. The Project Manager mentioned that the remote control should only be used for television and not for lighting adaptive functions.
2. The Industrial Designer proposed using a battery and two programmable chips for the remote control, with one chip handling communication via infrared and the other for functionalities.
3. The User Interface suggested integrating speech recognition with a limited vocabulary to allow users to select TV programs by voice commands.
4. Marketing pointed out that the remote control should be slim, small, and have a reasonable cost while including features like speech recognition and multilingual teletext support.
5. The Industrial Designer indicated that the remote control should not be wired and that it should be designed to work with conventional TVs without requiring a specific model.
6. The Marketing team suggested adding a microphone to the remote control to enable speech recognition functionality.
7. The Project Manager confirmed that the team would not need lighting adaptive options due to the new project requirements.
8. The Industrial Designer proposed anticipating future demands by designing the remote control to be compatible with internet-enabled TVs.
9. The Marketing team emphasized that the remote control should include features such as speech recognition, multilingual teletext, and be affordable to consumers.
10. The User Interface noted that the processing of data should occur on the TV set rather than the remote control, given the TV's processing capabilities.

PILOT LARGE FACTS
1. The meeting aims to present progress and make decisions on the design and functionality of a new television remote control.
2. Teletext is considered outdated due to the popularity of the internet, and it is decided that adaptive lighting is unnecessary for the remote control.
3. The industrial designer proposes using batteries embedded in the remote control instead of relying on external power sources.
4. Communication between the remote control and TV will be via infrared technology.
5. Two programmable chips are suggested: one for software functionalities (FPGA) and another for communication (Bluetooth).
6. A charger is proposed as an alternative to replaceable batteries to improve user convenience.
7. The user interface design emphasizes simplicity, focusing on navigation buttons rather than numerous small ones.
8. Speech recognition is proposed for limited tasks such as channel selection and volume adjustment, but its feasibility on small devices is questioned.
9. Processing should ideally occur on the TV set itself rather than the remote controller to ensure compatibility with existing models.
10. Feedback from users collected via magazine forms indicates interest in slim, inexpensive remotes with speech interfaces and multilingual support.
11. There is debate over including teletext and language options, though it is noted that these may not be essential for the current project.
12. The team agrees to consider future-proofing the remote control for potential internet-based TV features in upcoming models.
